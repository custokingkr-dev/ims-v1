# Student photo ownership follow-up

The compatibility `POST /api/v1/workspace/students` route previously copied its request map directly into student creation. An authorized creator could supply a raw private-bucket `photoUrl` pointing at a known object belonging to a different student. The canonical creation route already filtered raw keys, so the bypass was specific to the compatibility path and its shared repository. Subsequent photo reads and export used the stored key without checking that its bucket namespace belonged to the selected student.

The fix rejects caller-supplied raw keys inside `StudentReadRepository.createStudent` before any SQL or storage work, covering both entry points. Existing server upload/import workflows assign their generated keys through their own paths. Controlled legacy HTTP inputs retain compatibility behavior; they are not fetched as private object keys.

Photo content and export now select the school's immutable `school_uid` from owner SQL and pass it with the numeric student ID to storage. Attendance uses the same owner binding when minting a signed URL. Scoped storage accepts only flat image names under `schools/<canonical-school-uid>/students/<student-id>/photos/`. Foreign school/student IDs, other object classes, nested paths, traversal and encoded legacy URL paths fail before cloud access. Unscoped legacy storage signatures fail closed.

Stored-photo reads fetch bounded metadata, require an image content type and positive size/generation, then read exactly the observed generation with a generation-match precondition. Reads enforce the configured byte ceiling with a 16 MiB hard maximum, verify the actual size, limit concurrency to eight tasks with no waiting queue, and apply an eight-second whole-call deadline. SDK connect/read/total limits and one attempt come from the existing bounded storage client. Failures log constant messages without raw object keys or provider exceptions.

Regression checks cover the real compatibility controller calling the repository, real PostgreSQL rejection without a persisted student, foreign owner keys reaching no cloud method, valid scoped upload/sign/read/export behavior, replaced generations, active document metadata, byte ceilings and metadata timeouts.
