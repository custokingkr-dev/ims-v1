Ubuntu libpng 1.6.43-5ubuntu0.7's active CVE patch has the same ordered 19 added and 14 removed lines as the [upstream commit](https://github.com/pnggroup/libpng/commit/aa77ef38c17ab2fc1b41bec09fb973c6a386641d). Both selected images already report 0.7. Publisher source archive bytes match the [.dsc checksum](https://archive.ubuntu.com/ubuntu/pool/main/libp/libpng1.6/libpng1.6_1.6.43-5ubuntu0.7.dsc); the signature and source-to-binary correspondence were not verified. The current Canonical affected-range/scanner disagreement stays open.

Exact [Noble zlib source publication](https://archive.ubuntu.com/ubuntu/pool/main/z/zlib/zlib_1.3.dfsg-3.1ubuntu2.2.dsc) contains gzwrite.c identical to [upstream 1.3](https://raw.githubusercontent.com/madler/zlib/v1.3/gzwrite.c). It has neither gz_vacate nor EAGAIN, and none of eight active distro patches modifies that file. The named path exists in [upstream 1.3.2](https://raw.githubusercontent.com/madler/zlib/v1.3.2/gzwrite.c). This supports a specific source mismatch; Canonical still reports the package affected and installed binary correspondence remains unverified.

The old unzip attempt is unavailable/incomplete evidence: it masked command failures and never inspected nested JARs. Empty output is not absence. The dated named daemon/helper checks still bind three retained Java digests; they do not bind the two replacement images. Both current images were unavailable for local binary inventory; no images were pulled or started.

The saved HTTP2 length mismatch is correctly constructed and remains a conformance failure: reset code 2 is INTERNAL_ERROR, while [RFC9113 section 8.1.1](https://www.rfc-editor.org/rfc/rfc9113.html#section-8.1.1) requires PROTOCOL_ERROR for detected malformed messages. This does not identify the emitting component or prove downstream exposure. [Cloud Run's documented HTTP2 handling](https://docs.cloud.google.com/run/docs/configuring/http2) is context, not a readback of live configuration. No new probe ran.

All 186 approved historical acceptance JSON files match their saved raw-byte hashes. No tracked source, package policy, vulnerability suppression or cloud resource changed. No additional supported Noble package fix was established; the already-applied libpng backport and the exact zlib discrepancy are the new actionable facts.
