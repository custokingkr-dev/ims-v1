Security-state requests admit at most8 simultaneous calls,10sec whole fetch/body deadline and64KB responses. Document IDs are SHA256 hashes with separate consumed/revoked namespaces; cookies, nonces and identities are not stored in plaintext. State contains only expiry timestamps and hashed capability identifiers. OAuth state expires after10minutes; session cookies expire after12hours. Firestore TTL cleanup may lag; presence beyond expiry is safe because expired cookies are independently rejected. Removing an email from the deployed allowlist denies subsequent authenticated requests without waiting for cookie expiry.

The compatibility synchronous auth helpers remain for local unit tests. The server calls async wrappers for read/revoke/consume; all deployed requests use durable state. Local maps are bounded10,000 entries and purged by expiry. A failed consumption remains fail-closed and requires a fresh OAuth flow. A failed durable logout does not falsely report successful global revocation.

## Rollout and recovery

Use the dashboard's existing image vulnerability gate and immutable artifact review. Provision the dedicated named DB/TTL and restricted IAM, confirm managed SESSION_SECRET is at least32 random bytes and pinned HTTPS public URL matches OAuth registration, then deploy. With two instances, consume one captured valid authorization flow concurrently (one claim may succeed); log out on one instance and verify the identical captured session cookie denies on the other/revision. Deny access to the default and other databases. Exercise Firestore outage and verify no authenticated data is served. Verify TTL cleanup, monitoring bounds/alerts and costs.

Keep the stable secret during ordinary rollout to preserve deliberate session behavior. During emergency global logout rotate the managed secret across all revisions; until every old revision is drained, old revisions can still validate old-key cookies. Retain durable revocations for their capability lifetime plus deployment overlap. Never clear replay/revocation records to recover service while their corresponding cookies remain valid; rotate the session secret and drain old revisions first. A rollback to the old per-instance implementation weakens shared revocation, so requires full key rotation/drain and a coordinated release decision. Named database deletion protection prevents an accidental Terraform teardown.

Public Cloud Run reachability continues to be protected by application auth; optional load-balancer/IAP choices remain existing infrastructure policy. The new application startup guard does not establish that live ingress or IAP is correct. Monitoring results may report failed panels when the allowed series budget is exceeded; reduce cardinality/approved panel filter rather than relaxing limits blindly. Shared-cache work can continue up to its30sec deadline after one client leaves because other coalesced readers may remain; this is bounded retained work.
