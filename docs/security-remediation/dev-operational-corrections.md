# Dev operational corrections and limits

The successful final application release is [37524985447](https://github.com/custokingkr-dev/ims-v1/actions/runs/37524985447), source `9509d20c`. These subsequent source and controlled test corrections are recorded separately; they do not imply that the final application images were rebuilt with documentation or orchestration-only changes.

| Correction | Observed behavior and resulting verification |
| --- | --- |
| Windows PowerShell 5 serialization | `ConvertTo-Json` traversed provider metadata attached by `Get-Content` and stalled before producing a job manifest. Reading a plain string fixed it before any job was created. The real PowerShell 5 fixture exercises six serving-revision metadata inputs and the rendered job. |
| Signed probe deadline | The original bounded 10-second probe produced incomplete evidence: 12 checks, six passed and six failed with `REQUEST_FAILED`. The recorded error does not establish a definitive cause. A later bounded probe used 30-second requests, a 240-second total deadline and a 300-second job timeout; all 15 unique checks plus completion passed, and the exact job was independently confirmed absent. |
| Pub/Sub acknowledgement deadline | Reporting repair initially failed because the helper asserted a 10-second acknowledgement deadline without setting it; an existing 60-second value remained. Explicit `--ack-deadline=10` was added. Idempotent repair and independent metadata readback passed without weakening the assertion. Metadata success does not prove broker delivery. |
| Scheduler header argument | Create requires `--headers`; update requires `--update-headers`. The helper now selects the correct argument and retains POST, exact OIDC identity/audience and bounded attempt deadline. Controlled tests cover both branches. |

Actual controlled reruns passed four Python/PowerShell wrapper tests (one Windows PowerShell 5 serialization and three Pub/Sub cases), three Node signed-probe cases, two Scheduler argument branches, six image-config verification tests, three catalog-collator tests and 13 secret-revocation/readiness tests. These are operational regression tests, separate from the application CI totals. No controlled fixture performed live cloud mutations.

Live Scheduler history preserves initial failures instead of discarding them. The final request readback has 37 requests: 27 returned 200 and ten earlier requests returned 403. The latest request for each of the five authenticated targets returned 200, and all five jobs are enabled with correct POST/OIDC configuration. This establishes authenticated request delivery, not SMTP receipt, provider delivery, queue exhaustion or a broker restart/replay drill.

The [current ledger](IMPLEMENTATION-STATUS.md) and [release report](dev-security-release.md) remain authoritative for completed and open acceptance criteria. Sampled capacity metrics do not prove every old instance drained, the source 198-connection model, workload SLOs or database memory headroom. Configured image User does not observe the actual Cloud Run process UID. Retained shared-role ACLs remain a migration baseline, while shared LOGIN is disabled and its sessions are zero.
