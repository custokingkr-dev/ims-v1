# Owner-policy HTTP and database lock boundaries

Broadcast approval and live queueing now read an unlocked PostgreSQL row snapshot, fetch authoritative school-core recipient decisions outside any database transaction, then acquire the broadcast lock and compare the entire snapshot including PostgreSQL xmin. Concurrent edits, even a change followed by restoration of the old visible fields, invalidate that review with HTTP 409. Recipient-policy and preview fingerprints remain mandatory.

Both broadcast workers read a candidate in a short transaction, release it before the owner-policy HTTP request, then lock that exact candidate and compare recipient and broadcast revisions, bindings, attempts, due eligibility and dispatch mode. A competing worker completing the row makes the candidate ineligible. Changes while waiting for the broadcast lock are detected by a second revision read. A stale candidate never reserves a live provider submission or records a delivery outcome. Policy transport failures retain safe bounded preparation retry behavior.

Live preparation now additionally applies the complete NotificationPolicyGuard contract under the lock, including school, student, source-event, guardian, destination, consent, preference and evidence expiry. Lock waiting cannot extend evidence validity. The durable submission reservation still commits before the provider network request; uncertain results remain non-retryable automatically. Owner consent cannot be atomic across independent services: this preserves the existing two-minute server-issued evidence window and performs a new owner-policy fetch per attempt. No locally cached authorization replaces it.

Verification: full platform Maven suite passed 385 tests, zero failures/errors/skips, on 2026-10-07. This includes six real PostgreSQL broadcast repository tests, twelve privacy projection/restore tests, twelve live-worker tests and existing dispatch/dry-run worker coverage. The new PostgreSQL slow-policy test stalls the policy request, performs a concurrent update with a 500ms lock timeout, then proves approval fails without recipient inserts. The other new PostgreSQL test proves an ABA broadcast edit and a competing terminal recipient outcome invalidate exact claims. Controlled live-worker tests prove policy HTTP has no active transaction, stale snapshots do not prepare/reserve/send, and expired evidence suppresses before any provider call.

The local test log is an uncommitted temporary artifact (`tmp/platform-policy-lock-full-suite.log`); Maven XML reports provide per-class totals. This source change has not yet been deployed. Generic notification inbox provider I/O remains inside its existing delivery transaction; it does not perform the owner-policy HTTP calls addressed here. No claim is made that this change eliminates every network operation in every transaction.
