01Request flow, top to bottom

Every browser call enters one public gateway. It verifies the JWT, injects a per-service internal token, stamps trusted tenant headers, and proxies to the single service that owns the route — preserving the legacy /api/v1/** contract end to end.

Cyan lines animate in the direction requests travel — the four steps trace one API call end to end.

02How services talk to each other

Beyond the browser path, a few services make authenticated synchronous calls to peers. They forward the trusted X-Authenticated-* headers, add the peer's token, and (in Cloud Run) mint a Google OIDC token. No service ever reads another's tables.

Arrows point from caller to callee. billing makes no synchronous peer calls — it only publishes events.

identity → school-core

Resolve school & zone names during RBAC provisioning; sync zone-admin assignments.

operations → school-core

Check the school's active module entitlement before serving /ff endpoints — fails closed.

platform → school-core

Write superadmin approve / reject decisions onto supply orders (a projection only reads).

platform → operations

Write approve / reject decisions onto firefighting requests.

04The asynchronous event stream

Cross-domain read models are built from events, never shared tables. A domain write and its outbox row commit in one transaction; a relay publishes a canonical envelope; platform-service projects it — idempotently, keyed on eventId.

Gold lines animate in the direction events flow, left to right.

Producer — appends an outbox row in the same DB transaction as the domain change. Pub/Sub — transports the canonical envelope, at-least-once. Consumer — records each eventId once (idempotent), then projects it. Read model — query-optimized tables the dashboard reads.

05Delivery & guardrails

Deployment is branch-owned. Dev is where images are built and validated; production only ever promotes a digest that already passed in dev.

Request path Security boundary Tenant isolation Release & async

Branch-owned pipeline

  • Push to dev → fast direct Cloud Run deploy of affected services, using content-addressed images.
  • Push to main → Cloud Deploy canary; only dev-approved digests are eligible.
  • No active stage; no cloudbuild.yaml (retired).
5%→25%→50%→stable

Gateway enforcement

  • Local HS512 JWT verify on enriched claims; identity introspection fallback.
  • Per-service token injected; client-spoofable x-authenticated-* headers stripped.
  • Strict CORS allowlist, HSTS / CSP, body-size cap, token-bucket rate-limit.

Tenant isolation

  • Application-level school_id scoping from scoped role assignments.
  • PostgreSQL RLS backstop via app.current_school_id / app.bypass_rls GUCs.
  • Platform admins bypass filters; RuntimeDbRoleGuard pins the runtime role.

Release verification

  • Exact image-digest & Trivy gates per service.
  • Ready revision at 100% traffic; /gateway-health returns UP.
  • Serial prod rollout order to stay within the 20-vCPU quota.
